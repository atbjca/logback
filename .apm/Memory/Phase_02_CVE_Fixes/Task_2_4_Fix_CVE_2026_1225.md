# Task Log: Task 2.4 - 修复 CVE-2026-1225（配置文件任意类实例化）

## Summary
Added superclass type restriction to `NestedComplexPropertyIA` component instantiation, preventing arbitrary class instantiation via `class` attribute in logback configuration files. Commit: `e237e1bd8`.

## Details
- Adapted from official 1.5.x fix (commit `d28931f3b`) — NO 1.3.x backport existed for this CVE
- 1.5.x uses `ImplicitModelHandler` (model-based) vs 1.2.x `NestedComplexPropertyIA` (SAX-based action)
- 1.5.x uses `AggregationAssessor` vs 1.2.x `PropertySetter` with `BeanDescription`
- Four-part implementation:
  1. Added `expectedPropertyType` field (with getter/setter) to `IADataForComplexProperty`
  2. Added `getTypeForComplexProperty(String, AggregationType)` to `PropertySetter` — leverages existing `getRelevantMethod()` and `getParameterClassForMethod()`
  3. Added `instantiateClassWithSuperclassRestriction(Class<?>, Class<?>)` to `OptionHelper` — mirrors 1.5.x but uses `classObj.newInstance()` (Java 6 compatible) instead of `classObj.getConstructor().newInstance()`
  4. Modified `NestedComplexPropertyIA`: stores expected type in `isApplicable()`, uses restricted instantiation in `begin()`
- Vulnerable line was `componentClass.newInstance()` at line 121 of `NestedComplexPropertyIA.begin()` — now replaced with `OptionHelper.instantiateClassWithSuperclassRestriction(componentClass, expectedPropertyType)`

## Compatibility Notes
- Java 1.6 source level: multi-catch (`InstantiationException | IllegalAccessException`) not available, used `catch (Exception e)` instead
- `IncompatibleClassException` constructor is package-private, but `OptionHelper` is in the same `ch.qos.logback.core.util` package, so accessible
- Null-safe: if `expectedPropertyType` is null (shouldn't happen for valid AS_COMPLEX_PROPERTY/AS_COMPLEX_PROPERTY_COLLECTION), the superclass check is skipped

## Important Findings

3. **Existing infrastructure:** 1.2.x already had `IncompatibleClassException`, `DynamicClassLoadingException`, and `getRelevantMethod()`/`getParameterClassForMethod()` in `PropertySetter`, making the adaptation straightforward
